어려웠던 점: FastAPI의 get, post 메소드 등의 기초적인 활용만 필요했던 탓에 사용법 숙지가 어렵지는 않았음
                  모델의 사용 시에 내가 사용하는 하드웨어의 부족함을 평소에는 느낀 적이 없었지만 AI로 이미지, 동영상을 생성 시
                  왜 GPU가 중요하다고 하는 지 알 수 있었음. 또한, 전체적인(RAM, VRAM) 메모리 관리의 중요성을 깨달을 수 있었음
                  인공지능에게 얼마나 세부하게 프롬프트를 주느냐에 따른 결과물과 소요시간 차이를 파악하고, 프롬프트 엔지니어링의 
                  중요성을 다시한번 깨달았음

-동시 요청 처리 속도 개선 방안 탐색
어려웠던 점: 아침에 갑작스럽게 동시 요청 처리가 필요하다는 요구사항이 들어와 모델별 순차 처리로 만들던 것을 병렬처리로 구현할 필요성이 생김.
                  병렬 처리를 구현 시에 여러 혹은 동일 모델을 동시에 로드해야 하기 때문에 메모리 부족을 해결할 필요가 있었음. 이를 해결하기 위해 
                   번역 모델을 cpu에 로드해 gpu 부하를 줄이고, 이미지 생성 모델은 파라미터 조절 및 모델 별 사용 VRAM 규정을 통해 현재 사용 중인
                  VRAM에 여유 공간이 있으면 Load 아니면 대기하다가 Load 방식으로 구현. 만약 Load 시에 요청 사항과 동일 모델이 이미 Load 되어있다면 
                  Load 해제하지 않고 그대로 사용하게끔 함. 하지만 Load 시에 속도가 느려 Postman의 Performance 테스트 시에 1분을 초과해 ESOCKETTIMEOUT 에러
                 가 발생함.

Postman 사용 동시 요청 테스트 진행
테스트 결과에 따른 동시 요청 처리 시간 및 자원 소모 개선 방안 탐색
어려웠던 점: 여전히 병렬처리를 위해 필요한 여러 요소들을 확보하기 위해 방안을 탐색함. 또한 사용자가 여러 모델을 선택할 수 있게끔 하는 기능 추가 필요.
                 동시요청을 위해서는 병렬처리가 필요한데 이는 동시요청의 빠른 처리를 위해서임. 병렬 처리는 많은 메모리를 요구하고 
                 만약 이미 파이프라인에 로드되어 있는 것과 다른 모델을 로드하게 되면 교체 시간 때문에 처리 시간이 늦어지는 상황이 발생함
                 이를 위해 파이프라인 풀을 현재 하드웨어에 맞게 각 모델 별 두개를 생성해놓고 요구 시마다 각 모델별 병렬처리가 이루어지도록 개선함.
                 SD_1.5 모델은 해결되었지만 여전히 SD_3.5M 모델은 메모리 소모가 커 생성이 느림.

웹 UI 구현 및 테스트
어려웠던 점: 현재 프로젝트는 테스트를 위한 프로그램을 만드는 것이기 때문에 산출 결과물 보다는 속도가 중요하다고 함. 따라서 상업용 라이센스를 신경쓸
                 필요가 없어져 모델 선택의 자유도가 늘어남. 또한, 병렬처리가 아닌 순차처리로의 변경과 비디오 생성 모델의 추가, 웹 페이지의 구현이 필요해짐.
                 GPT, Perplexity, Claude 등 AI의 활용으로 보다 높은 퀄리티의 프로젝트 수행이 가능해졌지만 그 만큼 소프트웨어의 이해와 흐름 및 구조 파악의 중요성
                 이 증가했다는 생각이 들었음.

어려웠던 점: 순차처리로 구조가 변경되었으므로 이미지보다는 영상 생성에 집중하기로 함. 테스트 용이므로 결과물의 완성도보다는 생성 속도가 중요했으므로
                  파라미터를 조정해 빠르게 나오면서도 적절한 완성도를 보이는 균형점을 찾기로함. Wan2.1_1.3B 모델 조정 후에는 다른 적용할만한 모델을 찾음.

이미지 생성 후 경로 및 메세지 반환을 해야함
따라서, 요청은 계속 들어오는데 첫 번째 요청을 처리 중이므로 요청이 밀림

그렇게 밀린 요청은 ESOCKETTIMEDOUT 처리됨
--병렬처리 필요

해결방안
요청이 들어오는대로 최대n개(메모리 허용하는대로)까지의 요청에 필요한 모델 로드, 
병렬 처리 후 다음 요청이 이미 로드되어있는 모델이라면 계속해서 처리, 
만약 요청이 새로 들어왔고 아직 로드되어있는 모델들이 처리가 끝나지 않은 상태이며 vram이 남아있다면 새 모델 로드해서 해결
만약  vram이 가득차있다면 현재 작업 끝나는 대로 모델로드 후 처리
vram이 허용범위로 남아있다면 모델 추가 로드 후 작업 처리 ( 1.5 = 5, 3.5M = 6)
