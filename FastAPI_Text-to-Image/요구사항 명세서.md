# 요구사항 명세서 

## 1. 개요

- **목적**: 사용자가 웹에서 모델과 프롬프트를 입력하면, 프롬프트를 번역 후 이미지 또는 영상을 생성하여 파일로 반환하는 AI 생성 서버 구현
- **특징**: 번역 및 이미지/비디오 생성 모델을 파이프라인 풀로 관리하며, 모든 처리는 동기(순차) 방식으로 동작
- **아키텍처**: FastAPI 기반 REST API 서버, 파이프라인 풀 기반 모델 관리, GPU 메모리 최적화


## 2. 주요 기능 및 흐름

### 2.1 핵심 기능

- **모델 및 프롬프트 입력**: 웹 UI에서 모델과 프롬프트 입력
- **프롬프트 번역**: 한글 프롬프트를 영어로 번역 (facebook/nllb-200-distilled-1.3B)
- **이미지/비디오 생성**: Stable Diffusion 계열 및 Wan 계열 모델로 생성
- **결과 반환**: 생성된 파일을 `outputs/` 폴더에 저장하고, 경로 및 메시지 반환
- **파이프라인 풀**: 각 모델별로 최대 1개 인스턴스만 관리, 요청은 순차적으로 처리


### 2.2 GPU 메모리 관리

- **적응적 최적화**: GPU 메모리 용량에 따른 자동 최적화 설정
- **메모리 락**: 스레드 안전성을 위한 GPU 메모리 락 구현
- **폴백 메커니즘**: 모델 로딩 실패 시 대체 모델 경로 시도


## 3. API 엔드포인트

| 엔드포인트 | 메서드 | 설명 |
| :-- | :-- | :-- |
| `/image-models` | GET | 사용 가능한 이미지 생성 모델 목록 반환 |
| `/video-models` | GET | 사용 가능한 비디오 생성 모델 목록 반환 |
| `/generate-image` | POST | 이미지 생성 요청 (모델명, 프롬프트 입력) |
| `/generate-video` | POST | 비디오 생성 요청 (모델명, 프롬프트 입력) |
| `/download/{filename}` | GET | 생성된 이미지/비디오 파일 다운로드 |

## 4. 입력 및 출력 명세

### 4.1 이미지 생성 요청

**입력 (SimpleImageRequest)**

- `model_name`: 이미지 생성 모델명 (`SD_1.5`, `SD_3.5M`)
- `prompt`: 생성 프롬프트 (한글/영어)

**출력**

- `message`: 처리 결과 (`OK` 또는 `ERROR`)
- `image_path`: 생성 파일 경로 (`outputs/` 내 파일명)
- `task_id`: 요청 고유 ID
- `error`: 오류 발생 시 오류 메시지


### 4.2 비디오 생성 요청

**입력 (SimpleVideoRequest)**

- `model_name`: 비디오 생성 모델명 (`Wan_1.3B`)
- `prompt`: 생성 프롬프트 (한글/영어)

**출력**

- `message`: 처리 결과 (`OK` 또는 `ERROR`)
- `image_path`: 생성 파일 경로 (`outputs/` 내 파일명)
- `task_id`: 요청 고유 ID
- `error`: 오류 발생 시 오류 메시지


### 4.3 생성 파라미터

**이미지 생성 기본 설정**

- 해상도: 512x512
- 추론 스텝: 20
- 가이던스 스케일: 5
- 네거티브 프롬프트: "blurry, low quality, distorted, deformed, bad anatomy"

**비디오 생성 기본 설정**

- 해상도: 256x256
- 프레임 수: 33
- 추론 스텝: 25
- 가이던스 스케일: 5.0
- FPS: 15


## 5. 사용 모델 및 링크

| 구분 | 모델명 | HuggingFace 경로 | VRAM 사용량 |
| :-- | :-- | :-- | :-- |
| 번역 | facebook/nllb-200-distilled-1.3B | facebook/nllb-200-distilled-1.3B | CPU 전용 |
| 이미지 생성 | SD_3.5M | stabilityai/stable-diffusion-3.5-medium | 6GB |
| 이미지 생성 | SD_1.5 | stable-diffusion-v1-5/stable-diffusion-v1-5 | 5GB |
| 비디오 생성 | Wan_1.3B | Wan-AI/Wan2.1-T2V-1.3B-Diffusers | 4GB |

### 5.1 모델별 데이터 타입

- **SD_3.5M**: torch.bfloat16
- **SD_1.5**: torch.float16
- **Wan_1.3B**: torch.float16
- **번역 모델**: CPU에서 동작


## 6. 시스템 구성 및 파일 역할

| 파일명 | 주요 역할 | 핵심 기능 |
| :-- | :-- | :-- |
| `shared.py` | 전역 상태 관리 | 모델 캐시, 번역 모델/토크나이저, 파이프라인 풀(Queue) 및 락 관리 |
| `Translate.py` | 번역 서비스 | 번역 모델 초기화, 한글→영어 프롬프트 번역, CPU 전용 추론 |
| `ModelLoad.py` | 모델 관리 | 모델 로딩, 파이프라인 풀 관리, GPU 메모리 최적화, 파이프라인 획득/반환 |
| `Text_to_Image_Multi.py` | API 서버 | FastAPI 서버, 엔드포인트 구현, 요청 처리, 파일 다운로드 |

### 6.1 ModelLoad.py 주요 기능

- **적응적 GPU 최적화**: 12GB 이상, 8GB 이상, 8GB 미만에 따른 차별화된 최적화
- **파이프라인 풀 관리**: Queue 기반 파이프라인 인스턴스 관리
- **메모리 안전성**: GPU_MEMORY_LOCK을 통한 스레드 안전 보장
- **폴백 메커니즘**: 모델 로딩 실패 시 대체 경로 시도


### 6.2 최적화 전략

- **고사양 GPU (12GB+)**: attention_slicing 활성화
- **중간 사양 GPU (8GB+)**: attention_slicing + model_cpu_offload
- **저사양 GPU (8GB 미만)**: sequential_cpu_offload + VAE 최적화


## 7. 주요 처리 흐름

### 7.1 서버 시작 시

1. 번역 모델 초기화 (CPU)
2. 각 생성 모델을 1개 인스턴스로 로드하여 파이프라인 풀에 저장
3. GPU 메모리 상태에 따른 최적화 설정 적용

### 7.2 이미지/비디오 생성 요청

1. 요청 검증 (지원 모델 확인)
2. 프롬프트 번역 (한글 → 영어)
3. 파이프라인 풀에서 해당 모델 인스턴스 획득 (최대 120초 대기)
4. 생성 파라미터 설정 및 추론 실행
5. 결과를 `outputs/` 폴더에 저장
6. 파이프라인 인스턴스를 풀에 반환
7. 결과 메시지와 파일 경로 반환

### 7.3 파일 다운로드

- `/download/{filename}` 엔드포인트를 통해 파일 반환
- 파일 형식별 MIME 타입 자동 설정 (PNG, MP4, GIF)


## 8. 동작 및 리소스 관리

### 8.1 동기 처리 방식

- **순차 처리**: 모든 요청은 한 번에 하나씩 처리
- **타임아웃 관리**: 파이프라인 획득 시 120초 타임아웃
- **메모리 정리**: 각 요청 완료 후 GPU 캐시 정리


### 8.2 파이프라인 풀 관리

- **Queue 기반**: 각 모델별로 최대 1개 인스턴스 관리
- **스레드 안전**: 모델별 개별 락 사용
- **자동 복구**: 파이프라인 반환 실패 시 로깅 및 복구


### 8.3 메모리 최적화

- **GPU 메모리 모니터링**: 실시간 VRAM 사용량 추적
- **가비지 컬렉션**: 요청 완료 후 자동 메모리 정리
- **모델 캐싱**: 최초 1회만 로드, 이후 재사용
