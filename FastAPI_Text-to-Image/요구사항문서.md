# 요구사항 명세서 (최신화)

## 1. 개요

- **목적**: AI 기반 번역 및 이미지 생성 모델을 활용하여, 사용자가 웹사이트를 통해 프롬프트와 모델을 선택하면 이미지를 생성하고 결과 반환 구현
- **특징**: 번역 모델과 이미지 생성 모델을 효율적으로 관리하며, 동시 요청 처리와 파이프라인 풀링을 통해 성능을 최적화
- **아키텍처**: 파이프라인 풀 기반 병렬 처리 시스템으로 동일 모델의 다중 인스턴스 지원


## 2. 핵심 기능 흐름

- **모델 및 프롬프트 입력**: 사용자가 웹 UI에서 모델과 프롬프트를 입력
- **번역 처리**: 한글 프롬프트를 영어로 번역 (facebook/nllb-200-distilled-1.3B, CPU 모드)
- **파이프라인 풀 관리**: 모델별 독립적인 파이프라인 인스턴스 풀에서 사용 가능한 파이프라인 획득
- **이미지 생성**: Stable Diffusion 계열 모델로 이미지 생성 (GPU 메모리 적응적 최적화)
- **결과 반환**: 생성된 이미지를 서버에 저장하고, 성공 메시지와 이미지 경로를 반환
- **동시 요청 처리**: 세마포어와 파이프라인 풀을 통해 여러 사용자의 동시 요청 처리


## 3. 상세 요구사항

### 3.1 API 엔드포인트

1. **GET /models**
    - 사용 가능한 모델 목록과 각 모델별 예상 이미지 생성 시간 반환
    - 응답 형식: `{"available_models": [{"model_name": "SD_1.5", "estimated_time_seconds": "50초"}, ...]}`
2. **POST /generate-image**
    - **입력**: 모델명, 프롬프트, 해상도 (height, width)
    - **처리**: 프롬프트 번역 → 파이프라인 획득 → 이미지 생성 → 파일 저장 → 파이프라인 반환
    - **출력**: 성공 메시지, 이미지 경로, 태스크 ID 반환
3. **GET /status**
    - 현재 활성 태스크 수, 로드된 모델 수, GPU 메모리 사용량, 병렬 처리 설정 반환
4. **GET /health**
    - 시스템 헬스 체크 (CUDA 가용성, 활성 태스크 수, 병렬 처리 모드)
5. **GET /memory**
    - GPU 메모리 사용량 상세 정보 (할당량, 예약량, 최대 사용량, 총 용량)
6. **GET /download/{filename}**
    - 생성된 이미지 파일 다운로드

### 3.2 병렬 처리 및 성능 최적화

- **동일 모델 병렬 처리**: `PARALLEL_SAME_MODEL = True` 설정으로 같은 모델의 여러 인스턴스 동시 실행
- **최대 인스턴스 수**: `MAX_SAME_MODEL_INSTANCES = 2`로 모델당 최대 2개 인스턴스
- **전역 동시성 제어**: `MAX_CONCURRENT_GENERATIONS = 2`로 전체 시스템 부하 관리
- **세마포어 기반 제어**: 모델별 독립적인 세마포어로 동시 접근 제어

## 5. 시스템 구성 및 주요 모듈

| 파일명 | 주요 역할 및 기능 요약 | 최신 특징 |
| :-- | :-- | :-- |
| `shared.py` | 모델 캐시, 번역 모델, 파이프라인 풀 전역 객체 관리 | 파이프라인 풀(`pipeline_pools`) 및 락(`pipeline_pool_locks`) 추가 |
| `Translate.py` | 번역 모델 초기화 및 프롬프트 번역 함수 제공 | CPU 전용 모드로 최적화, 메모리 효율성 개선 |
| `ModelLoad.py` | SD 모델 로딩, 파이프라인 풀 관리, GPU 메모리 적응적 최적화 | 다중 인스턴스 생성, 파이프라인 획득/반환 시스템, GPU 메모리 기반 최적화 |
| `Text_to_Image_Multi.py` | FastAPI 서버, 비동기 이미지 생성, 동시성 제어 | 세마포어 기반 병렬 처리, 파이프라인 풀 통합, 태스크 추적 시스템 |

## 6. 파이프라인 풀 아키텍처

### 6.1 풀 관리 시스템

- **모델별 독립 풀**: 각 모델마다 별도의 `Queue` 기반 파이프라인 풀 운영
- **동적 인스턴스 생성**: GPU 메모리 상황에 따른 최적 인스턴스 수 자동 계산
- **안전한 획득/반환**: 타임아웃 기반 파이프라인 획득 및 자동 메모리 정리

## 8. 동시 요청 및 리소스 관리

### 8.1 동시성 제어 메커니즘

- **전역 세마포어**: `generation_semaphore = asyncio.Semaphore(2)` - 전체 시스템 동시 처리 제한
- **모델별 세마포어**: 각 모델마다 독립적인 세마포어로 병렬 처리 제어
- **파이프라인 풀 락**: `threading.Lock`을 통한 풀 접근 동기화
- **태스크 추적**: `active_tasks` 세트를 통한 활성 태스크 모니터링


### 8.2 메모리 관리 전략

- **자동 메모리 정리**: 각 요청 완료 후 `torch.cuda.empty_cache()` 및 `gc.collect()` 실행
- **파이프라인 반환**: 사용 완료된 파이프라인 자동 풀 반환으로 리소스 재활용
- **GPU 메모리 모니터링**: 실시간 메모리 사용량 추적 및 최적화


### 8.3 성능 최적화 특징

- **병렬 인스턴스**: 동일 모델의 여러 인스턴스로 처리량 향상
- **비동기 처리**: FastAPI의 비동기 기능을 활용한 논블로킹 처리
- **적응적 최적화**: GPU 메모리 상황에 따른 동적 최적화 설정
- **효율적 번역**: CPU 기반 번역 모델로 GPU 리소스 절약


## 9. 주요 처리 흐름

1. **요청 접수**: 클라이언트로부터 이미지 생성 요청 수신
2. **동시성 제어**: 전역 및 모델별 세마포어 획득
3. **번역 처리**: 한글 프롬프트를 영어로 번역 (CPU)
4. **파이프라인 획득**: 모델별 풀에서 사용 가능한 파이프라인 인스턴스 획득
5. **이미지 생성**: GPU에서 Stable Diffusion 모델로 이미지 생성
6. **파일 저장**: 생성된 이미지를 `outputs/` 폴더에 저장
7. **리소스 반환**: 파이프라인 풀 반환 및 메모리 정리
8. **응답 전송**: 성공 메시지와 이미지 경로를 클라이언트에 반환
